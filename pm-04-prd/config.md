# pm-04-prd 설정

이 파일은 PRD 한 장의 **칸, 후보 수, 성공 기준 모양**을 정합니다.
여기를 고치면 다음에 돌릴 때 PRD가 달라집니다. 고친 뒤에는 "config.md 바꿨어. 다시 해줘"라고 말합니다. 개조 포인트 1과 3은 S5부터, 2는 S2부터 다시 합니다.
개조 포인트 3곳 말고는 고치지 않습니다.

<!-- ⚙️ 개조 포인트 1 · PRD에 어떤 칸을 둘까 -->
> 여기를 내 서비스에 맞게 고치세요.
> 지금 값: 한 줄 소개부터 아직 모르는 것까지 10칸
> 고치는 법: 줄을 지우거나 더합니다. 순서가 PRD의 순서입니다
> 이걸 바꾸면: 원본 docs/02-PRD.md, 기획안 html, pdf 의 칸 이름과 순서가 바뀝니다. 지운 칸은 S5에서 묻지 않습니다

```yaml
prd_sections:
  - 한 줄 소개
  - 문제
  - 대상
  - 출발점 (3회차)
  - 이번에 만들 기능
  - 저장할 것 (6회차)
  - 기록할 행동 (7회차)
  - 성공 기준 (8회차)
  - 나중에 (지금은 안 만듦)
  - 아직 모르는 것
```

"이번에 만들 기능" 칸 아래에는 늘 `### 동작 순서` 가 붙습니다.
목록에 없던 칸을 더하면 S5에서 클로드가 그 칸의 초안도 한 줄 적어 함께 보여 줍니다.
<!-- /개조 포인트 1 -->

<!-- ⚙️ 개조 포인트 2 · 서비스 후보와 기능을 몇 개로 할까 -->
> 여기를 내 서비스에 맞게 고치세요.
> 지금 값: 서비스 후보 3개, 이번에 만들 기능 1개
> 고치는 법: 숫자만 바꿉니다
> 이걸 바꾸면: S2에서 보여 주는 서비스 후보 수와, S4에서 고르는 기능 수가 바뀝니다

```yaml
direction_candidates: 3
features_now: 1
```

`features_now` 는 1을 권합니다. 2 이상으로 올리면 S4가 "정말 둘 다 5회차에 만들 수 있나요?"를 한 번 더 묻고, PRD의 "이번에 만들 기능" 칸에 기능마다 이름과 동작 순서를 따로 적습니다.
<!-- /개조 포인트 2 -->

<!-- ⚙️ 개조 포인트 3 · 성공 기준을 어떤 모양으로 쓸까 -->
> 여기를 내 서비스에 맞게 고치세요.
> 지금 값: [누가] [어디서] [무엇을] [얼마 안에] 한다 · 2개 · 기한 10월 4일 5회차 수업 끝
> 고치는 법: 모양, 개수, 기한 중 바꿀 것만 바꿉니다
> 이걸 바꾸면: PRD "성공 기준" 칸의 문장 모양과 개수, 기한 줄이 바뀝니다

```yaml
success_form: "[누가] [어디서] [무엇을] [얼마 안에] 한다"
success_count: 2
success_deadline: "10월 4일 5회차 수업 끝"
```
<!-- /개조 포인트 3 -->
