# pm-04-prd 참고

SKILL.md 가 단계마다 가리키는 자리입니다. 필요한 절만 읽습니다.

## §1 아쉬운 점 보기 (S1)

보기를 그대로 보여 준다. 수강생은 번호만 골라도 된다.

### 과정에서 아쉬웠던 점

| 번호 | 보기 |
|---|---|
| 가1 | 쓸 만한 공공데이터를 찾는 데 오래 걸렸다 |
| 가2 | 인증키 받기와 넣기에서 막혔다 |
| 가3 | 클로드에게 원하는 화면을 말로 설명하기 어려웠다 |
| 가4 | 고쳐 달라고 할 때마다 다른 곳이 바뀌었다 |
| 가5 | 인터넷에 올리는(배포) 단계에서 막혔다 |
| 가6 | 무엇을 만들지 정하는 데 시간이 가장 많이 들었다 |

### 결과물에서 고치고 싶은 점

| 번호 | 보기 |
|---|---|
| 결1 | 보기만 하고 할 수 있는 일이 없다 |
| 결2 | 내 상황(지역, 시간, 관심사)에 맞게 좁혀 보기 어렵다 |
| 결3 | 볼 때마다 처음부터 다시 골라야 한다. 내 것이 남지 않는다 |
| 결4 | 휴대폰에서 보기 불편하다 |
| 결5 | 숫자와 표만 있어서 그래서 뭘 하라는 건지 모르겠다 |
| 결6 | 다른 사람과 같이 보거나 나누기 어렵다 |

"가"는 과정에서 결과물 문제로 이어지지 않는 경우가 많다. 가3, 가4, 가6은 **새 서비스 A**의 재료가 되기 좋다. 예: "매번 설명하기 어려웠다"에서 "요청 문장을 저장해 두는 서비스".
"결"은 **대시보드 키우기 B**의 재료가 되기 좋다.

## §2 서비스로 키우는 5가지 길 (S2)

보기만 하는 화면에 **사람이 하는 일 하나**를 더한다. 대부분 아래 5가지 중 하나다.

| 길 | 사람이 하는 일 | 남는 것 | 잘 맞는 아쉬운 점 |
|---|---|---|---|
| 기록 | 내가 한 일을 적는다 | 내 기록 목록 | 결1, 결3 |
| 제보 | 지금 본 것을 알린다 | 다른 사람이 보는 정보 | 결1, 결6 |
| 저장 · 찜 | 마음에 드는 것을 모은다 | 내 목록 | 결2, 결3 |
| 입력과 계산 | 내 숫자를 넣는다 | 내 결과 | 결2, 결5 |
| 공유 | 링크로 남에게 보낸다 | 같이 보는 화면 | 결6 |

후보를 낼 때는 **아쉬운 점에 가장 가까운 길**부터 적는다. 5가지 모두를 억지로 채우지 않는다.

### 후보 예시

**B 대시보드 키우기** · 3회차에 "서울 공공자전거 대여소 현황"을 만들었고, 아쉬운 점이 결2와 결3인 경우

```
후보 1 · 내 대여소 · B 대시보드 키우기 · 저장 · 찜 · 아쉬운 점 결2, 결3에서
  사람이 하는 일   대여소 옆 별표를 누른다
  남는 것          내 대여소 목록 (대여소 번호, 이름, 저장한 날짜)
  줄어드는 불편     매번 대여소를 다시 찾지 않고, 열자마자 내 대여소 3곳만 본다
```

**A 새 서비스** · 아쉬운 점이 가3 "원하는 화면을 말로 설명하기 어려웠다"인 경우

```
후보 2 · 요청 문장 수첩 · A 새 서비스 · 기록 · 아쉬운 점 가3에서
  사람이 하는 일   잘 통한 요청 문장을 적고 "잘 됨" 표시를 누른다
  남는 것          요청 문장 목록 (문장, 무엇에 썼나, 잘 됨 여부)
  줄어드는 불편     다음에 비슷한 화면을 만들 때 처음부터 설명하지 않는다
```

## §3 빈칸 채우기 틀과 좋은 문장, 나쁜 문장 (S3 · S5)

### 빈칸 채우기 틀

| 칸 | 틀 | 채운 예 |
|---|---|---|
| 문제 | [누가] [언제] [무엇을 하다가] [무엇이 불편하다] | 퇴근길 직장인이 저녁 7시에 자전거를 빌리러 갔다가 자전거가 없어 다른 대여소를 찾아 걷는다 |
| 대상 | [무엇을] [얼마나 자주] 하는 사람 | 퇴근길에 같은 대여소 2~3곳을 주 3번 이상 쓰는 사람 |
| 동작 순서 | 사용자가 [무엇]을 본다 → [무엇]을 누르거나 적는다 → 화면에 [무엇]이 생긴다 | 대여소 목록을 본다 → 대여소 옆 "☆"를 누른다 → 화면 맨 위 "내 대여소"에 한 줄이 생긴다 |
| 저장할 것 | [항목 이름] · [예시 값] | 대여소 번호 · 01234 |
| 기록할 행동 | [버튼 이름]을 누를 때 1번 | "☆"를 누를 때 1번 |
| 성공 기준 | [누가] [어디서] [무엇을] [얼마 안에] 한다 | 내가 휴대폰에서 내 대여소 3곳의 남은 자전거 수를 10초 안에 본다 |

### 좋은 문장과 나쁜 문장

| 칸 | 나쁜 문장 | 좋은 문장 |
|---|---|---|
| 문제 | 따릉이가 불편하다 | 퇴근길에 대여소에 갔는데 자전거가 없어서 다른 대여소를 찾아 걷는다 |
| 대상 | 20~30대 직장인 | 퇴근길에 같은 대여소 2~3곳을 번갈아 쓰는 사람 |
| 기능 | 편하게 즐겨찾기할 수 있게 한다 | 대여소 옆 별표를 누르면 "내 대여소" 목록 맨 위에 한 줄이 생긴다 |
| 성공 기준 | 사용하기 편하다 | 내가 휴대폰으로 열어 10초 안에 내 대여소 3곳의 남은 자전거 수를 본다 |
| 저장할 것 | 사용자 정보 | 대여소 번호, 대여소 이름, 저장한 날짜 |

**문제 칸에는 해결책을 적지 않는다.** "즐겨찾기가 없다"는 해결책을 뒤집은 말이다. 불편을 적는다.

## §4 기능 고르는 물음 2개 (S4)

| 물음 | ⭕ | ❌ 또는 🔺 |
|---|---|---|
| 이것만 있어도 쓰나 | 나머지가 다 없어도 이것 때문에 연다 | 다른 기능이 있어야 의미가 있다 |
| 5회차 1시간에 만들 수 있나 | 화면 하나, 버튼 1~2개, 이 기기에 남기면 된다 | 로그인, 여러 사람이 같이 보기, 알림, 결제가 필요하다 |

표시 2칸이 모두 ⭕ 인 것에 ⭐ 를 붙인다. ⭐ 가 없으면 "이것만 있어도 쓰나"가 ⭕ 인 것 중 가장 작은 것을 권한다.

## §5 PRD 틀 (S6 · S7)

원본 `docs/02-PRD.md` 의 틀이다. 기획안 `docs/02-PRD.html` 은 이 원본을 `assets/prd-template.html` 에 옮겨 만든다.

## §6 점검 7가지 (S6)

**처음 보는 개발자가 이 한 장만 받았다**고 치고 읽는다.

| | 묻는 것 | 걸리는 예 |
|---|---|---|
| 1 | 기능이 `features_now` 개인가 | 기능 칸에 "그리고"로 이어진 기능이 둘 |
| 2 | 동작 순서에 **보이는 것 · 누르는 것 · 생기는 것**이 다 있나 | "저장한다"만 있고 어디에 무엇이 생기는지 없음 |
| 3 | 성공 기준을 눈으로 확인할 수 있나 | "편하다", "많이 쓴다" |
| 4 | 저장할 것이 동작 순서와 맞나 | 순서에는 메모를 적는데 저장할 것에 메모가 없음 |
| 5 | 모르는 말이 있나 | 설명 없는 줄임말, 앱 안에서만 쓰는 이름 |
| 6 | 출발점과 이어지나 | 아쉬운 점 어느 것도 줄이지 않는 기능이 됨 |
| 7 | 성공 기준을 기한 안에 확인할 수 있나 | 기한은 10월 4일인데 "5일 동안 3번"처럼 그 뒤에야 알 수 있음 |

걸린 곳은 "어디가 · 왜 · 이렇게 고치면" 한 줄로 보여 준다. 고칠지는 수강생이 정한다.

## §7 pdf 뽑기 (S7)

기획안 `docs/02-PRD.html` 을 컴퓨터에 있는 크롬이나 엣지로 pdf로 저장한다. 따로 설치하지 않는다.

1. 브라우저를 찾는다. 앞에서부터 처음 있는 것을 쓴다.

| 컴퓨터 | 찾을 자리 |
|---|---|
| 맥 | `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` |
| 맥 | `/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge` |
| 윈도우 | `C:\Program Files\Google\Chrome\Application\chrome.exe` |
| 윈도우 | `C:\Program Files (x86)\Google\Chrome\Application\chrome.exe` |
| 윈도우 | `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe` |

2. 찾은 브라우저로 아래처럼 뽑는다. 경로에 빈칸이 있으면 큰따옴표로 감싼다.

```bash
"(찾은 브라우저)" --headless=new --disable-gpu --no-pdf-header-footer \
  --print-to-pdf="docs/02-PRD.pdf" "file:///(기획안의 전체 경로)"
```

3. `docs/02-PRD.pdf` 가 생겼고 크기가 10KB 보다 크면 된 것이다.

### 손으로 pdf 만들기

브라우저를 못 찾았거나 2번이 실패하면 수강생에게 이렇게 안내한다.

```
1. 왼쪽 파일 목록에서 docs/02-PRD.html 을 오른쪽 클릭해 "Reveal in Finder"(윈도우는 "Reveal in File Explorer")를 누릅니다
2. 파일을 두 번 눌러 브라우저로 엽니다
3. 맥은 Cmd + P, 윈도우는 Ctrl + P 를 누릅니다
4. 대상(프린터)을 "PDF로 저장"으로 바꾸고, "배경 그래픽"에 체크합니다
5. docs 폴더에 02-PRD.pdf 라는 이름으로 저장합니다
```

## §8 안 되실 때

| 증상 | 원인 | 이렇게 |
|---|---|---|
| 3회차 과제를 못 했다 | 과제를 건너뛰었다 | S1 ①②를 요즘 불편으로 받고, ④는 새 서비스로 둔다. 출발점 칸의 "3회차에 만든 것"은 "없음" |
| 아쉬운 점이 하나도 안 떠오른다 | 빈칸이라 막막하다 | §1 보기에서 번호만 고르게 한다. 그래도 없으면 결1 "보기만 하고 할 수 있는 일이 없다"를 예로 들어 묻는다 |
| 후보가 마음에 안 든다 | 후보가 아쉬운 점과 멀다 | "아쉬운 점 (번호)에 더 가깝게 3개 더"라고 말한다 |
| 새 서비스와 키우기 사이에서 못 고르겠다 | 둘 다 좋아 보인다 | 5회차 1시간에 만들 수 있는 쪽을 권한다. 대시보드가 이미 인터넷에 올라가 있으면 B가 빠르다 |
| 기능을 하나로 못 고르겠다 | 다 필요해 보인다 | "이것만 있고 나머지가 없어도 내가 쓰나?"를 하나씩 묻는다 |
| CLAUDE.md 에 이미 규칙이 많다 | 1회차에 길게 만들었다 | 기존 줄은 두고 `## 이 폴더에서 할 일` 절에 2줄만 더한다 |
| 재개했는데 고른 것이 없다 | 진행상황.md 에 "고른 것" 줄을 안 적은 단계다 | 그 단계만 다시 묻는다. 수강생 기억에 기대지 않는다 |
| pdf가 안 생기거나 비어 있다 | 브라우저가 없거나 경로에 막혔다 | §7 끝의 "손으로 pdf 만들기"를 안내한다. html만 있어도 S7 저장은 끝난 것이다 |
| pdf에서 어두운 칸이 하얗게 나온다 | 배경 그래픽이 꺼져 있다 | 손으로 뽑을 때 "배경 그래픽"에 체크한다 |
